# generative recommendation overview

ブレインパッドの解説記事「Generative Recommendation（生成型推薦）」の内容を、レコメンド技術の世代史・パラダイムシフト・代表3手法・実装課題の観点で詳細にまとめたもの。

## 1. レコメンド技術の3世代史

生成型がなぜ飛躍なのかを理解する土台として、記事はレコメンドを3世代に整理している。

### 第1世代：協調フィルタリングと行列分解
- 仕組み: ユーザー×アイテムの相互作用行列を低次元の潜在空間に投影し、ベクトルのドット積で相関を捉える
- 本質: 過去の類似性を統計的に補完するだけ
- 代表手法: MF（Matrix Factorization）、BPR、NCF、RecVAE

### 第2世代：深層学習による系列モデリング
- 仕組み: MLP やアテンション（Transformer）を導入し、非線形・長期依存をモデル化
- 代表手法: GRU4Rec、SASRec、BERT4Rec
- 限界: 推薦を「候補に点数をつける識別的スコアリング」として扱うため意味的知識を使えない。コールドスタートとポピュラリティ・バイアスを根本解決していない
- 補足: 現行の DeepFM ベースのランキング（ID 埋め込み + スコアリング）はこの第2世代の位置づけにあたる

### 第3世代：生成型推薦（Generative Recommendation）
- LLM の登場で「ID マッチング」から「意味（セマンティクス）の理解」へ。データ・モデル・タスクの3レベルで転換が起きる

## 2. データ・モデル・タスクの3層の転換

記事の中核フレーム。

### データレベル：ID依存からの脱却
- LLM の膨大な知識を前提に、テキストや文脈から好みを推論
- 履歴ゼロの新規ユーザー／新商品でも推論可能＝コールドスタート克服
- さらに LLM でユーザーの潜在意図を推論し、不足するインタラクションを擬似合成してデータの希薄さを能動的に補完

### モデルレベル：推薦を「単語生成プロセス」として再定義
- アイテムを記号ではなく「意味情報を保持したトークン」として扱う
- 表層的な共起ではなく、より深いセマンティックな依存関係を捉える
- LLM 同様のスケーリング則（モデルを大きくすると性能が上がる）が効く

### タスクレベル：受動的ツールから対話型アシスタントへ
- 説明可能性: なぜこれが最適かを自然言語で説明
- 対話能力: 曖昧な要望を会話で洗練し、結果をその場で修正できる多段階推薦

## 3. 代表3手法の深掘り

3手法は「どのレベルの進化か」が異なり、運用ハードルも対照的。

### (1) ActionPiece（DeepMind, 2025）— モデルレベル
狙い: アイテムを ID から「文脈で形が変わるセマンティック・トークン」へ昇華。

処理ステップ:
1. セットのシーケンス処理: 1アイテムを {カテゴリ, ブランド, 価格, タイトル} という順序のないセットとみなし、購買ログをそのセットの時系列シーケンスとして扱う
2. 重み付き BPE: NLP のサブワード化（Byte Pair Encoding）を拡張。セット内＋隣接セット間での属性ペアの共起確率に基づき、頻出パターンを新しいセマンティック・トークンとして結合。文脈そのものを1トークンに圧縮できる
3. SPR（Set Permutation Regularization）: 学習時に属性の順序をランダムに入れ替え、集合には順序がないというバイアスを排除しつつ多様な分割を学習

実験: Amazon Reviews（Sports/Beauty/CDs）で SASRec・TIGER と比較し、NDCG@10 で最大12.82%改善。LLM をバックボーンに Fine-tuning、GPU 必須。

### (2) HSTU（Meta, 2024）— モデルレベル
狙い: 推薦専用の巨大モデル（LRM: Large Recommendation Models）をスクラッチで作り、スケーリング則を実証。汎用 Transformer を流用せず、推薦データ特有の性質（超大規模・非定常・長尺）に特化。

技術:
1. Pointwise Aggregated Attention: Softmax アテンションを廃止。Softmax は値を確率分布に正規化するため「100回買った」という強度がならされる。点単位の集計に変えることで頻度をそのまま反映でき、選好の強さ・滞在時間を正確に捕捉。精度と学習安定性を両立しつつ高速
2. Stochastic Length（SL）: 学習中に長い履歴を確率的にサンプリングし、計算量を抑えつつ 8,192 という長尺シーケンス学習を実現

実験: Amazon Review・MovieLens・1,000億規模の Meta 産業データで、SASRec や標準 Transformer（FlashAttention-2）と比較。HR@10 等で最大65.8%向上、学習速度で最大15.2倍高速化。スクラッチ学習が必要で24GB以上の GPU 必須＝最も運用ハードルが高い。

### (3) InteRecAgent（Microsoft, 2023）— タスクレベル
狙い: LLM を推薦エンジン本体ではなく、既存エンジン／検索ツールを操る「脳」にする。新規学習ナシで GPT-4 の対話・論理力と既存推薦システムの正確性を役割分担。

ツール構成: SQL作成（発売日・価格を調べる）／アイテム検索（条件で絞り込み）／ランキング計算（好みに合わせ順位付け）

技術:
1. Shared Candidate Bus: 候補を全部テキストで LLM に渡すとトークン制限に当たるため、候補をツール間共有のバスに保持し LLM には流さず管理。対話を止めずに数千件規模を絞り込める
2. Plan-first Execution: 先にツール呼び出しの全体計画を立ててから実行し応答遅延を最小化
3. Actor-Critic Reflection: 生成した計画を別 LLM が評価し自己修正

実験: Steam・MovieLens・Amazon Beauty で GPT-4 単体や Chat-Rec と比較し全指標で凌駕。化粧品ドメインでもハルシネーションを抑えつつ正確な推薦を維持。GPT-4(o-mini) を API 呼び出しするだけで CPU 環境でも動く＝最も導入が軽い。

## 4. セマンティック・トークンという考え方

3手法に共通する根幹概念。アイテムを無機質な ID ではなく「文脈で形が変わる可変トークン」として再定義することで、言語モデルの「次のトークンを当てる大規模学習」を推薦にそのまま適用できる。

## 5. 課題と結論

- 計算リソース: HSTU 級のスクラッチ学習は膨大な GPU（24GB以上）が必要
- エージェント運用コスト: API 推論コスト増・レイテンシ
- ハルシネーション: LLM 単体は信頼性に課題。既存システム連携で部分的に解決

結論: 精度向上と運用コストのトレードオフをどう見極めるかが、生成型をビジネス実装する鍵。

## 6. 導入の軽さ ↔ 性能上限の整理

- 軽い: InteRecAgent（API のみ、CPU 可、対話 UX が魅力）
- 中: ActionPiece（既存系列モデルの ID をセマンティック ID 化、Fine-tuning）
- 重い: HSTU（専用巨大モデルをスクラッチ、最大性能だが GPU 大量）
