# research

まとまった技術調査の成果物を 1 トピック 1 ディレクトリで保存する場所。

## 命名規則

- ディレクトリ名: 英語ケバブケース（例: `locust-load-testing`, `cache-strategy`）
- 内部ファイル名は自由だが、最初に読むべき要約として `overview.md` を置くことを推奨

## ディレクトリ構造の例

```text
research/
└── locust-load-testing/
    ├── overview.md   ← 最初に読む要約
    ├── ...           ← 実験コード、検証メモ、図など
```

## tech_knowledge との使い分け

| | tech_knowledge | research |
|---|---|---|
| 単位 | 1 ファイル | 1 ディレクトリ |
| 想定分量 | 数百行以内 | 複数ファイル・コード片を含む |
| 典型的な内容 | 単発 Q&A、仕様メモ | ライブラリ素振り、比較検証、段階的な調査ログ |

迷ったら `tech_knowledge/` に書き始め、膨らんだら `research/` に昇格させる方針でよい。

## 想定するユースケース

- ライブラリ検証（素振りコード込み）
- アーキテクチャ判断のための比較調査
- 設計パターン検討の途中メモ込み
- 負荷試験・性能調査などまとまった検証の記録

## 追加のしかた

規約に沿ったディレクトリを置いて `git add / commit / push` するだけでよい。

調査用の作業ディレクトリ（任意の場所で作成したもの）の中身を `research/{topic}/` にコピーして
コミットする運用が基本。一括化するヘルパースクリプトを使ってもよいが、必須ではない。

## 運用上の注意

- 同名トピックが既存の場合、上書き前に既存内容を確認する
- 機密情報（社名・個人名・トークンなど）が含まれていないか、保存前に必ず確認する
- 実験コードに認証情報や `.env` が混入していないかも要チェック
